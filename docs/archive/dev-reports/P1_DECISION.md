## 🎯 四个可选方案

### 方案 A：纯本地统计 ⚙️

**核心**: 从 oh-my-opencode 消息历史本地解析

```
优点:
✅ 零依赖，完全离线
✅ 控制力强
✅ 实时性强
✅ 无需配置 API Key

缺点:
❌ 精确性取决于消息完整性
❌ 定价表需手动维护
❌ 统计逻辑与厂商计费逻辑可能有偏差
❌ 无法处理 oh-my-opencode 外的使用

推荐用于: 快速启动，功能完整
```

**数据精度**: ⭐⭐⭐ (70-80%)  
**实现复杂度**: ⭐⭐ 简单  
**完成时间**: 7 天

### 方案 B1：混合方案 (主要厂商 API)

**核心**: 优先用厂商 API，无法获取时回退本地统计

**覆盖**: Anthropic + OpenAI (占成本的 ~70-75%)

```
优点:
✅ 两个主要厂商数据精确
✅ 定价自动更新
✅ 向下兼容 (没配置也能用)
✅ 配置简单 (仅需两个 API Key)

缺点:
⚠️ ZhiPu 仍需估算 (定价表维护)
⚠️ 需要网络连接
⚠️ 用户需配置 API Key

推荐用于: 传统混合方案
```

**数据精度**: ⭐⭐⭐⭐⭐ (95%+)  
**实现复杂度**: ⭐⭐⭐ 中等  
**完成时间**: 8 天

---

### 方案 B1+ (增强混合方案) 🎯 **强烈推荐 ⭐**

**核心**: API 集成 + ZhiPu 官方插件 (glm-plan-usage)

**覆盖**: Anthropic API + OpenAI API + ZhiPu 插件

```
优点:
✅ Anthropic 数据精确 (API)

⚠️ 用户需安装 glm-plan-usage 插件
⚠️ ZhiPu 插件需要 GLM API Key

推荐用于: 最优方案! 更精确，更快，更简单

**数据精度**: ⭐⭐⭐⭐⭐ (97%+) ⭐ 最佳!
