**关键定位修正**: 本项目是 **oh-my-opencode 的本地 Skill 工具**,而非企业级生产服务。

基于 [功能评估报告](FEATURE_EVALUATION_REPORT.md) 和用户新需求,提出 **Skill 适配的精简优化方案**:

- ✅ 删除企业级特性(监控、告警、日志基础设施)
- ✅ 聚焦核心价值(策略管理、智能推荐、动态生成)
- ✅ 整合配额感知和动态策略生成
- ✅ 保持轻量化和本地执行特性

### 1.2 配额感知推荐系统 (8-10h) ⭐ **新增**

**核心需求**: 根据配额剩余情况智能调整推荐

**具体工作**:

1. **集成 UsageSync 数据** (3h)

   ```typescript
   interface QuotaStatus {
     provider: string;
     remaining: number; // 剩余额度(USD)
     total: number; // 总额度
     usagePercent: number; // 使用百分比
     resetDate: Date; // 重置日期
   }
   ```

   - 从 UsageSync 读取各厂商配额
   - 计算剩余额度百分比
   - 识别即将耗尽的配额

2. **动态权重调整** (3h)

   ```typescript
   // 原逻辑:固定权重
   const weights = {
     scenario: 0.4,
     cost: 0.3,
     quality: 0.2,
     history: 0.1,
   };

   // 新逻辑:配额感知权重
   function getQuotaAwareWeights(quotaStatus: QuotaStatus[]) {
     // 配额充足:优先质量
     // 配额不足:优先成本
     // 配额即将用尽:强制低成本策略
   }
   ```

3. **成本预警集成** (2-3h)
   - 推荐时显示预估成本 vs 剩余配额
   - 超预算时自动推荐经济策略
   - 生成配额使用报告

4. **测试和验证** (1-2h)
   - 模拟不同配额场景
   - 验证推荐准确性

**验收标准**:

- ✅ 配额不足时自动推荐低成本策略
- ✅ 显示"预估成本 vs 剩余配额"对比
- ✅ 支持多厂商配额综合评估

### 1.3 性能优化(保留轻量版) (2h)

**简化目标**: 保留关键性能优化,删除复杂缓存

1. **并行化验证** (2h)

## Phase 2: 动态策略生成 (8-12h) ⭐ **新增核心功能**

**目标**: 除预置模板外,支持动态生成定制化策略
**优先级**: 🔥 **强烈推荐**
**ROI**: ⭐⭐⭐⭐⭐ 极高(核心差异化功能)

### 2.1 策略生成器 (4-5h)

**核心逻辑**: 基于场景 + 配额 → 智能生成策略

**具体工作**:

1. **模板选择引擎** (1.5h)

   ```typescript
   function selectBaseTemplate(
     scenario: ScenarioType,
     quotaStatus: QuotaStatus[],
   ): StrategyTemplate {
     // 1. 根据场景选择最佳基础模板
     // 2. 考虑配额限制(如 Anthropic 不足→不选 super/performance)
     // 3. 返回深拷贝,避免修改原模板
   }
   ```

2. **智能模型替换** (2h)

   ```typescript
   function optimizeAgentModels(
     template: StrategyTemplate,
     quotaStatus: QuotaStatus[],
     priority: Priority,
   ): StrategyTemplate {
     // 遍历所有 agent,根据配额动态调整:
     // - Anthropic 不足 → 替换为 ZhiPu/OpenAI
     // - OpenAI 不足 → 替换为 ZhiPu/Gemini
     // - 优先级=cost → 选择低成本模型
     // - 优先级=quality → 保持高质量模型
   }
   ```

3. **参数智能调优** (0.5-1h)

   ```typescript
   function tuneParameters(agent: Agent, scenario: ScenarioType): Agent {
     // 根据场景调整:
     // - coding: temperature 0.2-0.3
     // - creative: temperature 0.7-0.8
     // - research: maxTokens 更大
     // - daily: maxTokens 更小
   }
   ```

4. **生成元数据** (0.5h)
   - 记录生成时间、基础模板、调整原因
   - 生成唯一标识符

**验收标准**:

- ✅ 支持 13 种场景类型
- ✅ 配额不足时自动替换模型
- ✅ 生成的策略通过 schema 验证
- ✅ 保留生成溯源信息

### 2.2 临时策略管理 (2-3h)

**具体工作**:

1. **临时策略存储** (1h)

   ```bash
   # 目录结构
   ~/.config/opencode/
   ├── oh-my-opencode.json          # 当前策略
   ├── strategies/                   # 预置模板(8个)
   └── dynamic-strategies/          # 动态生成的策略
       ├── generated-coding-202602041530.jsonc
       └── generated-research-202602041600.jsonc
   ```

2. **生命周期管理** (1h)
   - 自动清理过期临时策略(默认 7 天)
   - 支持"固化"临时策略为正式策略
   - 列表显示时标注来源(预置/动态)

3. **CLI 集成** (0.5-1h)

   ```bash
   # 生成策略
   bun run manage-strategies generate \
     --scenario coding \
     --priority balanced \
     --quota-aware

   # 列出所有策略(含动态生成)
   bun run manage-strategies list --include-dynamic

   # 固化临时策略
   bun run manage-strategies save-dynamic \
     generated-coding-202602041530 \
     my-custom-coding
   ```

**验收标准**:

- ✅ 动态策略自动保存到独立目录
- ✅ 支持列表、切换、删除操作
- ✅ 可转换为正式策略

### 2.3 场景识别增强 (2-3h)

**目标**: 提升推荐准确率 70% → 85%

**具体工作**:

   interface UserHistory {

   - 时间段识别(工作日/周末、工作时间/休闲时间)

3. **智能权重优化** (0.5h)
   - 结合历史偏好调整场景匹配权重
   - 学习用户选择反馈(推荐→实际选择)

**Phase 2 效果**:

- 评分提升: 95.5 → 96.5+ (+1+分)

## 附录

### 关键设计决策

**为什么删除监控系统?**

- 本地 Skill 工具用户就是开发者本人
- 无需 24/7 监控和告警
- 简单的 CLI 输出和日志文件即可满足需求

**为什么删除 A/B 测试?**

- 本地单用户环境无法有效进行 A/B 测试
- 策略效果高度依赖个人使用场景,无法统计显著性
- 用户可以手动切换策略对比,无需框架

**为什么优先动态策略生成?**

- 这是核心差异化功能
- 直接解决用户痛点(8 个预置模板不够用)
- 与配额感知推荐形成完整闭环
- 技术实现相对简单,ROI 很高

**为什么保留 UsageSync 集成?**

- 配额感知是智能推荐的核心基础
- UsageSync 已经实现,直接复用
- 本地执行,无性能问题
