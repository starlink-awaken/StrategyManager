# 策略对比工作流

描述：对比两个策略配置并高亮显示差异的标准化工作流，参考 ManageStrategies.ts 中的 compareStrategies 实现逻辑。

触发条件：
- 手动触发：用户在 StrategyManager 界面选择两个策略并点击“比较”。
- 自动触发：在策略保存或版本发布时，由 CI/任务调度触发对比（可选）。

执行步骤：
1. 输入准备
   - 接收两个策略对象（A、B）。每个策略包含至少：id、name、version、rules、parameters、metadata。
2. 规范化
   - 将策略字段按统一顺序展开（扁平化或结构化），确保可比性。
   - 对缺失字段填充显式空值以便比较。
3. 字段逐项比较
   - 对每个字段执行严格比较：值相等 -> 标记为相同；值不等 -> 标记为不同并记录对比详情。
   - 对数组或对象类型，递归比较内部字段；对规则集合按规则 id 匹配比较。
4. 差异高亮与分类
   - 将差异分类为：新增字段（仅存在于B）、删除字段（仅存在于A）、修改字段（同名字段值不同）。
   - 对于数值/阈值变更，额外标注变化幅度（如果适用）。
5. 输出格式化
   - 生成结果结构：{ summary: { equalCount, diffCount, added, removed, modified }, details: [ { fieldPath, type, valueA, valueB, note } ] }
   - 提供人类可读视图：表格或高亮 JSON，便于在 UI 中展示。
6. 验证与安全检查
   - 验证 compare 过程中无异常抛出；对未识别字段记录警告。
   - 若发现对关键字段（如策略状态、权限、阈值）有重大变更，添加审查标记并建议人工复核。
7. 返回结果
   - 将比较结果返回给调用者（UI/CI），并写入对比日志/审计记录（可选）。

验证方法：
- 单元验证：给定已知的策略对（完全相同、仅名称不同、有新增字段、有嵌套对象差异），compare 函数应返回正确的 summary 与 details。示例：
  - 相同策略 -> summary.diffCount == 0，details 为空数组。
  - 新增字段 -> details 包含 type='added' 且 fieldPath 对应新增字段。
- 集成验证：在 UI 中选择两个真实策略进行比较，视觉上高亮差异且可展开查看每项差异。
- 错误处理验证：传入不完整策略（缺 id/name）时，应返回可识别的错误或警告，而非抛出未捕获异常。

参考实现要点（基于 ManageStrategies.ts compareStrategies）：
- 规范化和字段填充是关键（避免因字段顺序或缺失导致误报）。
- 对数组（如 rules）应按元素唯一标识（id）匹配，而非纯位置比较。
- 记录每个差异的上下文（fieldPath）以便 UI 精确定位并高亮显示。

注意：
- 不要在此工作流中创建深层次子目录；文件必须位于指定目录下。
